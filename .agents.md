# .agents.md — guia de trabalho para IAs no YKS-Screen

## O que é este projeto

**YKS-Screen** é uma Activity do Discord que transforma um canal de voz numa sala de reunião privada (estilo Google Meet). Quem abre a Activity no mesmo canal entra na mesma sala e vê as telas/câmeras dos demais.

A **sala é o próprio canal de voz** (`roomId = channelId`), então cada canal = uma sala, com zero vazamento de mídia.

## Regra de ouro — 100% estático, sem servidor

Este projeto **é e deve continuar sendo um site 100% estático**:

- **Não há back-end**. Não existe servidor (Node, Python, Go, etc.) rodando nada.
- **Não há `npm install`, `package.json` de produção, `bun`, `deno`, `vite`, `webpack`, `esbuild` ou qualquer etapa de build.**
- Não é permitido adicionar dependências de runtime nem qualquer comando `install`/`build`/`dev` que exira ferramentas instaladas na máquina.
- O site é um conjunto de arquivos estáticos (`index.html`, `styles.css`, `app.js`, `mqtt.js`, `config.js`, `frames.js`, `broadcast.js`, `transport.js`, `capture.html`, `capture.js`, `capture.css`, `vendor/socket.io.min.js`) servidos diretamente via **GitHub Pages** (ou qualquer CDN/estático).
- Exceção documentada: a pasta `relay/` é um servidor Socket.IO **opcional** e fora do versionamento principal (`.gitignore`). Ela só é usada quando o usuário opta pelo transporte `socketio` com o próprio relay. Ela NÃO faz parte do site estático e NÃO deve ser requisitada para o projeto funcionar.

## Como funciona (arquitetura resumida)

1. A Activity roda dentro de um iframe no proxy do Discord (`https://<client_id>.discordsays.com`), sujeito a uma CSP rígida.
2. Tudo que a Activity precisa da internet passa por esse proxy, via **URL Mappings** configurados no Portal do Desenvolvedor do Discord (`/sdk`, `/broker`, `/relay`).
3. A mídia (vídeo VP8 via WebCodecs + áudio PCM) é empacotada em frames binários (`frames.js`) e roteada por um **broker MQTT público** (`broker.emqx.io:8084`, sem cadastro) usando um cliente MQTT próprio e sem dependências (`mqtt.js`).
4. Dois tópicos por sala: controle JSON (`hello`/`ping`/`bye`/`stream`/`stop`/`needkey`) com QoS 1, e mídia binária com QoS 0.
5. A captura de tela não pode ser feita dentro do iframe do Discord (sem `allow="display-capture"`), então existe uma **aba companheira** (`capture.html`) que roda fora do proxy (site real, sem a CSP restritiva) e publica os frames pelo mesmo transporte.

## Arquivos principais

| Arquivo | Função |
|---|---|
| `index.html` | Splash + interface da sala (Activity) |
| `app.js` | SDK do Discord + UI da sala + protocolo de presença + montagem de URLs de transporte |
| `capture.html` | Aba companheira: captura a tela fora do iframe |
| `capture.js` | Lógica da aba companheira (captura, publica frames, keyframe) |
| `capture.css` | Estilos da aba companheira |
| `config.js` | Parâmetros de mídia compartilhados (resolução, taxa, codec) |
| `frames.js` | Codec do frame binário (meta JSON + payload) e `randomId` |
| `media-errors.js` | Diagnóstico de captura (policy do iframe x cancelamento) |
| `transport.js` | Transportes: MQTT (padrão) e Socket.IO (relay próprio) |
| `broadcast.js` | Publicação: MediaStream → WebCodecs → frames → transporte |
| `mqtt.js` | Cliente MQTT 3.1.1 mínimo, sem dependências (~350 linhas) |
| `vendor/socket.io.min.js` | Cliente Socket.IO (MIT, vendorizado para não depender de CDN) |
| `relay/` | Servidor Socket.IO opcional (fora do versionamento principal) |

## O que NÃO fazer (importante para IAs)

- Não criar `package.json`, `node_modules`, `bun.lockb`, `package-lock.json`, `vite.config.*`, `webpack.config.*`, etc. no raiz do projeto.
- Não adicionar comandos de `install`/`build`/`dev`/`start` que requeiram ferramentas instaladas localmente.
- Não importar bibliotecas de CDN no código da Activity (exceto o `vendor/socket.io.min.js`, que já está local). O cliente MQTT é próprio.
- Não mudar o princípio de "sem servidor": se precisar de algo com estado/servidor, use a pasta `relay/` (opcional) ou o broker público MQTT, nunca o raiz do site estático.
- Não confiar em `<script src="https://...">` para o SDK do Discord dentro do Discord: a CSP do proxy bloqueia hosts externos (`cdn.jsdelivr.net`). O SDK deve vir pelo URL Mapping `/sdk`.

## Como testar localmente

Apenas sirva os arquivos estáticos:

```bash
python3 -m http.server 8000
```

Abra em duas abas (sem Discord, sala manual):

```
http://localhost:8000/index.html?room=minha-sala&user=aaa&name=Alice
```

Ou modo simulado (sem o Discord):

```
http://localhost:8000/index.html?mock=1&channel=111&user=aaa&name=Alice
```

Aba companheira (captura de tela de verdade):

```
http://localhost:8000/capture.html?capture=1&room=minha-sala&user=aaa&name=Alice
```

## Publicar

Enviar os arquivos estáticos para o GitHub Pages (ou qualquer host estático). Após cada publicação, trocar a versão nos `<script src="...?v=…">` e `<link href="styles.css?v=…">` de `index.html` e `capture.html` (cache do navegador e do proxy do Discord).

No Discord:
1. New Application → copiar o **Application ID** para `app.js` → `CONFIG.clientId`.
2. Ativar a Activity e apontar a **Activity URL** para o site publicado.
3. Configurar os **URL Mappings** (obrigatórios dentro do Discord): `/` → site, `/sdk` → `cdn.jsdelivr.net`, `/broker` → `broker.emqx.io:8084`.
4. Developer Mode ligado → canal de voz → botão 🚀.
